# Store and social graphics

Every image in this folder, and `store/product-hunt/thumbnail-240.png`, is
generated by [`store/tools/graphics.mjs`](../tools/graphics.mjs). Change the
script and run it again. Do not edit the PNGs by hand.

```bash
node store/tools/graphics.mjs              # render all six, then check each file
node store/tools/graphics.mjs og small     # only these
node store/tools/graphics.mjs --out=/tmp/g # write elsewhere, to compare before replacing
node store/tools/graphics.mjs --verify     # render nothing, only check the files
```

It needs Google Chrome (set `CHROME_PATH` if Chrome is not in `/Applications`)
and has no npm dependencies. A full run takes about 20 seconds.

## Files

| File | Size | Format | What it is | Where it goes |
|---|---|---|---|---|
| `promo-small-440x280.png` | 440×280 | 8-bit RGB PNG, no alpha | Small promo tile (**required**) | CWS Developer Dashboard → item → **Store listing** → Graphic assets → **Small promo tile** |
| `marquee-1400x560.png` | 1400×560 | 8-bit RGB PNG, no alpha | Marquee promo tile (optional; needed to be featured in the marquee) | Same page → **Marquee promo tile** |
| `store-icon-128.png` | 128×128 | 8-bit RGBA PNG | Store icon: 96×96 artwork in 16 px of transparent padding | Same page → **Store icon**. See [Store icon](#store-icon) for the icon inside the package. |
| `og-1200x630.png` | 1200×630 | 8-bit RGB PNG, no alpha | Open Graph and Twitter card for the landing page | `site/build.mjs` copies it to `graphics/og-1200x630.png`. `site/index.html` points `og:image` and `twitter:image` at that file. |
| `github-social-1280x640.png` | 1280×640 | 8-bit RGB PNG, no alpha | Repository social preview | GitHub → repo → **Settings** → General → **Social preview** → **Edit** → **Upload an image…** (PNG, JPG or GIF under 1 MB) |
| `../product-hunt/thumbnail-240.png` | 240×240 | 8-bit RGB PNG, no alpha | Product Hunt thumbnail | Product Hunt launch form → **Thumbnail** |

The Chrome Web Store takes promo tiles as JPEG or 24-bit PNG with no alpha.
The script re-encodes Chrome's screenshot as colour type 2 (RGB). Then it reads
each file back and checks the signature, the IHDR width and height, bit depth
8, the colour type, and that there is no `tRNS` chunk. The check reads the
bytes. It does not use another program's text output. `--verify` runs the
same check alone.

## Words

| Where | Line |
|---|---|
| Small tile | `Sort by views. Free.` It must read at 220×140, so it is set in 30 px type, and the strip fits 20 characters. |
| Marquee | `Best posts first. Free.` |
| OG and GitHub cards | `Best posts first.`, then `Sort any Instagram or TikTok profile by views, likes or outlier score.`, then chips `FREE` · `OPEN SOURCE` (OG) or `MIT` (GitHub) · `NO ACCOUNT` |

The CWS tiles do not name either platform. The two cards name them in plain
text only. No image uses an Instagram or TikTok logo, wordmark, icon or brand
colour, and nothing suggests affiliation. The grid is fictional: the dot-art
thumbnails, the scores and the counts are all invented.

## Design

The set uses the extension's reflective LCD look: panel `#c7e3ab`, ink
`#13200f`, dim `#4d6440`, the toolbar icon's four-bar bitmap, and the 5×7
metric icons from `src/content/runtime/dots.js`. The tiles copy the
extension's own grid: rank top left, outlier score top right, and the score
inverted from 2x up (`BADGE_MIN`), with counts along the bottom.

- **Type** is Matrix Sans Screen (`src/fonts`, SIL OFL 1.1). The images
  contain rendered text only; the font itself is not distributed with them.
  Each page embeds the font as bytes. If the face does not report `loaded`,
  the page paints itself red and the run fails. A fallback face therefore
  cannot slip through.
- **Sizes are multiples of 10 px.** The font draws on a 0.1 em dot grid, so
  every dot is a whole number of pixels.
- **The unlit-pixel texture has a 6 px pitch**, with 2×2 px dots at 9 %. The
  extension uses a 3 px pitch, which is what a 2x screen shows as 6. At a
  3 px pitch the texture moirés when an image is shown at half size. At 6 px
  it halves cleanly to 3.
- **Every image has an ink frame.** The panel is pale, and the store puts
  tiles on light grey, so the frame gives the tile a hard edge.
- **The icons are drawn pixel by pixel** (store icon, Product Hunt thumbnail),
  and the icon in the tiles is an SVG with whole-pixel coordinates. None of
  them is a scaled bitmap.

## Store icon

The Chrome Web Store asks for a 128×128 icon with **96×96 artwork and 16 px of
transparent padding per side**. `src/icons/icon-128.png` has 112×112 artwork
in 8 px of padding (bounding box of the opaque pixels: 8,8 to 119,119). It does
not meet the guideline.

`store-icon-128.png` meets it: the opaque box is 16,16 to 111,111. It uses
the same drawing as `scripts/make-icons.mjs`: 4 px frame, 2 px gap between
dots, dots 10 px instead of 12. It is byte-identical to what `make-icons.mjs`
writes for 128 with this spec:

```js
128: { pad: 16, border: 4, bitmap: BARS, pitch: 12, dot: 10 },
```

**The manifest's 128 icon should change to this spec too.** The store takes
the listing icon from the 128×128 icon in the uploaded ZIP ("You must provide
a 128×128-pixel extension icon image in the ZIP file"). Chrome also shows that
icon in the install dialog. With 8 px padding it draws about 17 % larger than
icons that follow the guideline, and its ink frame sits 8 px from the canvas
edge, where the store says its UI may add an edge of its own. To make the
change, edit that one line in
`scripts/make-icons.mjs` and run `npm run icons`. The 16, 32 and 48 icons are
drawn separately and do not change.
